# 华为笔记本充电保护

在华为笔记本上直接通过 **ACPI-WMI** 读写充电阈值，并查看电池容量与健康度的托盘小工具，
**不依赖华为电脑管家**（管家退出也能用）。

纯 Win32 / 纯 C 实现，无第三方运行库依赖，常驻系统托盘。

> 本说明只讲这个程序本身。仓库里用于逆向分析与验证的脚本，见 [tests/](tests/README.md)。

---

## 实测环境

下表是本机实测值，也是各项行为被验证时的实际环境。

| 项 | 值 |
|---|---|
| 机型 | **HUAWEI KLV-WX9**（MateBook 14） |
| 主板 | KLV-WX9-PCB (M1010) |
| BIOS | HUAWEI 1.26（2022-03-03） |
| 操作系统 | **Windows 10 Pro 22H2**，内部版本 **19045.6332**，x64 |
| 显示缩放 | 150%（DPI 144） |

> 换到别的机型不一定可用：部分机型的 BIOS 未开放华为 HWMI OEM 接口，
> 此时读取会失败（见下文「已知限制」）。

## 功能

| 功能 | 位置 |
|---|---|
| 当前电量 | 托盘图标悬浮即显示 |
| 出厂设计容量 / 当前满充容量 | 快捷菜单与设置窗口 |
| 电池健康度 | = 满充容量 ÷ 出厂设计容量 |
| 循环次数 / 电压 / 化学体系 | 设置窗口 |
| 设置充电**起始**与**截止**百分比 | 快捷菜单（粗档）+ 设置窗口（细档） |
| 开机自启 | 快捷菜单一键开关 |

健康度算法说明：满充容量会随电池老化下降，而设计容量是出厂标称值，
两者之比即为健康度。本机 48701 ÷ 56316 ≈ 86.5%。

## 构建

需要 **mingw-w64** 的 `gcc` 与 `windres` 在 `PATH` 中。

```
src\build.bat
```

产物输出到 `release\hwbattery.exe`。`release/` 已在 `.gitignore` 中，构建产物不入版本库。

> **产物文件名固定为 `hwbattery.exe`，请勿改名。** 它与产品名（华为笔记本充电保护）
> 是有意分开的：标题栏、PE 版本信息里显示中文产品名，而可执行文件仍叫这个名字，
> 文档与命令行示例都按它引用。

构建脚本会先用 `windres` 编译 `src\hwbattery.rc`（版本信息 + 应用清单 + 图标），
再与 `hwbattery.c` 链接。

## 使用

直接运行 `release\hwbattery.exe`，程序常驻托盘，不显示主窗口。

| 操作 | 结果 |
|---|---|
| 左键点击托盘图标 | 打开设置窗口 |
| 右键点击托盘图标 | 弹出快捷菜单 |

快捷菜单：

- **起始充电** —— `0 / 10 / … / 90`。选 `0` 表示不限制；其余为「低于 N% 才开始充」。
  当前生效值带勾选。
- **充电截止** —— `50 / 55 / … / 100`。当前生效值带勾选。
- 打开设置窗口 / 开机自启 / 刷新 / 退出

设置窗口里起止档位更细（步长 5），并可看到全部电池数值。

### 命令行开关

便于脚本化与排障：

```
hwbattery.exe --query                 读一次并输出，同时追加到 %TEMP%\hwbattery-autostart.log
hwbattery.exe --show                  启动即弹出设置窗口（可做快捷方式）
hwbattery.exe --autostart=on          设置开机自启
hwbattery.exe --autostart=off         取消开机自启
hwbattery.exe --autostart=query       查询开机自启状态
```

> 控制台里的中文可能因代码页显示为乱码，**以日志文件为准**：
> `%TEMP%\hwbattery-autostart.log`（UTF-8）。

### 权限

程序清单声明 `requireAdministrator`，**手动启动会申请管理员权限**。
原因是设置充电阈值必须提权，而配置文件里的期望阈值每次启动都要向固件下发一次。

**开机自启走任务计划程序，不用 Run 键。** 任务以 `/RL HIGHEST` 创建
（登录触发、最高权限、仅交互式），由计划程序直接拉起，**登录时不弹 UAC**——
这正是 Run 键做不到的（Run 键拉起的进程无法静默提权，每次登录必弹框）。
关闭自启即删除该任务，并顺带清掉历史遗留的 Run 键值。

## 原理

### 通道

```
root\WMI :  OemWMIMethod.OemWMIfun(u64Input   uint64      [in],
                                    u32Resrved uint32      [out],
                                    u8Output   uint8[256]  [out])
实例     :  InstanceName = 'ACPI\PNP0C14\HWMI_0'
GUID     :  ABBC0F5B-8EA1-11D1-A000-C90629100000
返回约定 :  u8Output[0] = 状态码（0 = 成功），其后为数据
```

### 命令字

命令字格式统一为 `0xNN03`，高字节 `NN` 是功能号：

| 命令字 | 功能 | 载荷（`[n]` 指 u64Input 的第 n 字节） |
|---|---|---|
| `0x1003` | 设置充电阈值 | `[2]=起始%` `[3]=截止%` |
| `0x1103` | 读取充电阈值 | 无入参 |
| `0x1203` | 设置恢复充电标志 | `[2]=标志` |
| `0x1303` | 读取恢复充电标志 | 无入参 |
| `0x1503` | 设置智能充电模式 | `[2]=模式` `[3]=0x48 或 a3` `[4]=起始` `[5]=截止` |
| `0x1603` | 读取智能充电模式与容量 | 无入参 |

本工具只用到 `0x1003`（写阈值）与 `0x1103`（读阈值）。
其余 `0x0e03` / `0x1403` / `0x1703` / `0x1803` 分别是 SOC 电源控制条件、
AC 供电时长、Prochot 原因、温度控制策略，与充电保护无关。

### 两条读取路径的返回布局**不同**，不可混用

- **`0x1103`** —— 在 256 字节返回区里**自末尾向前**找最后一个非零字节 `out[i]`（`i ≥ 2`），
  则 `起始 = out[i-1]`、`截止 = out[i]`。
- **`0x1603`** —— **固定偏移**：`out[1]` = 模式（须 `< 7`），`out[3]` / `out[4]` = 容量对。

本机实测两者指向同一个实际阈值：

```
0x1103 -> 00 55 5A                => 起始 85%  截止 90%
0x1603 -> 00 01 48 55 5A          => 模式 1，容量对 85 / 90
```

把 `0x1103` 的样本套到 `0x1603` 上（或反之）会解析出错误结果——`0x1603` 的
`out[1]` 是模式号，而 `0x1103` 的 `out[1]` 是起始百分比。

### 阈值写入的实际链路

本机反汇编显示，阈值写入在插件层与 WMI 层之间还有一个中间层：

```
SmartChargePlugin
  -> HardwareHal!Battery::SetChargeThreshold(const StBatteryChangeThresholdLimit*)
     -> WmiUtil!HwSDK::BiosWmi::SetBatteryChargeThreshlod(start, end)   [0x1003]
        -> ACPI-WMI
```

`StBatteryChangeThresholdLimit` 是 2 字节打包结构 `{ BYTE start; BYTE end; }`。

**该中间层不做任何范围校验**：`0..255` 任何字节都会原样下发给固件，
也没有「起始不得高于当前电量」之类的保护。程序里的校验（`0..100`、`起始 ≤ 截止`）
是为了避免写坏状态，不是固件要求。

## 已知限制

- **机型依赖。** 需要机型 BIOS 开放华为 HWMI OEM 接口。若读取失败，程序会明确显示
  「读取失败或本机未开放 HWMI」；本机（KLV-WX9）实测可用。
- **手动启动会弹 UAC。** 清单为 `requireAdministrator`；开机自启不受影响（见「权限」）。
- **硬件保护范围有限。** 通过本工具把起始阈值设得比当前电量还高又立刻拔电，
  只会让机器先放电到起始值再充，来回折腾反而增加循环次数。建议长期插电办公用
  `60 70` 或 `0 70`，出门前改回 `0 100` 充满。
